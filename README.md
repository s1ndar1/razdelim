# Разделим — прототип (FastAPI + PostgreSQL)

## Важная поправка к исходной идее

По актуальной документации Max (`dev.max.ru/docs/webapps/introduction`) ссылка вида
`https://max.ru/<botName>?startapp=<payload>` открывает **мини-приложение напрямую**,
а не «перекидывает в бота» — мини-апп получает `payload` через
`window.WebApp.initDataUnsafe.start_param` и работает независимо от диалога с ботом.

Поэтому в этом прототипе:
- вступление в сессию и подтверждение оплаты идут **прямо из мини-аппа** через `/join` и `/confirm`;
- диалог с ботом (`/webhook/max`, `bot_started`) нужен только как *опциональный* канал,
  чтобы бот мог уведомить организатора — и то только если тот уже сам стартовал бота ранее.

## Установка и запуск

```bash
cd razdelim
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# если вы используете локальный Postgres
# docker compose up -d
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Проверки:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/
```

Swagger-документация — на `http://127.0.0.1:8000/docs`.

## Эндпоинты

| Метод | Путь | Кто вызывает | Что делает |
|---|---|---|---|
| `GET` | `/health` | мониторинг/оперативка | проверяет, что API запущено и БД отвечает |
| `POST` | `/sessions` | организатор (из бота/мини-аппа) | создаёт `PaymentSession`, возвращает диплинк `?startapp=<token>` |
| `POST` | `/join` | мини-приложение при открытии | валидирует `initData` по HMAC, создаёт `Participant`, возвращает сумму и реквизиты |
| `POST` | `/confirm` | мини-приложение, кнопка «Я оплатил» | помечает участника `paid`, фоново уведомляет организатора |
| `GET` | `/sessions/{id}/status` | организатор | таблица участников и статусов |
| `POST` | `/webhook/max` | платформа Max | ловит `bot_started`, чтобы бот мог писать организатору |

## Безопасность

`app/security.py` реализует HMAC-SHA256-проверку `initData` строго по алгоритму из
`dev.max.ru/docs/webapps/validation`. **`user_id` берётся только из провалидированного
`initData`, никогда из тела запроса** — это защищает от подделки и является требованием
модерации Max для мини-приложений.

## Чего не хватает для продакшена

- регистрации самого бота и получения `BOT_TOKEN` (нужно юрлицо/ИП — резидент РФ);
- реального хостинга `static/index.html` по HTTPS и указания его адреса в настройках бота;
- вебхука на публичном HTTPS с CA-сертификатом (self-signed Max не принимает) — на
  хакатоне для этого обычно поднимают ngrok/cloudflared;
- обработки случая «участник передумал / организатор отменил сессию»;
- миграций (Alembic) — сейчас таблицы создаются через `SQLModel.metadata.create_all`,
  чего достаточно для прототипа, но не для эволюции схемы в проде.

## Файлы

```
app/
  config.py     — переменные окружения
  database.py   — подключение к Postgres
  models.py     — PaymentSession, Participant, BotUser
  schemas.py    — Pydantic-схемы запросов/ответов
  security.py   — HMAC-валидация initData
  bot.py        — отправка сообщений через Max Bot API
  main.py       — все эндпоинты
static/
  index.html    — скелет фронта мини-приложения
```
